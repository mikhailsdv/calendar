# Данные производственных календарей

```
data/
  countries/<id>.json      профиль страны: правила + справочник праздников
  years/<id>/<year>.json   конкретный год: только отличия от обычной недели
```

## Главная идея

Год хранится **как разница с обычной неделей**. Если даты нет в `days`, день определяется
по `week.weekend` страны. Так одна схема подходит и для пятидневки СНГ, и для США
(неделя с воскресенья), и для стран с выходными в пятницу и субботу.

Правила из профиля (`rule`, `weekendHoliday`) нужны только для **прогноза** будущих лет.
Если год подтверждён постановлением, источник правды — сам файл года (`status: "official"`).

## Типы дней (`days[date].type`)

Тип отвечает на вопрос «работаю ли я в этот день?».

| type         | работаю?  | смысл                                                                               | пример               |
| ------------ | --------- | ----------------------------------------------------------------------------------- | -------------------- |
| `holiday`    | нет       | нерабочий праздник. **Не списывается из отпуска** (RU/KZ/BY)                        | 9 мая                |
| `dayoff`     | нет       | выходной, но не праздник: перенос, мост. **Списывается из отпуска**                 | 11 мая 2026 в РФ     |
| `workday`    | да        | рабочий день вопреки обычной неделе (рабочая суббота) и/или сокращённый (`shortBy`) | 20.02.2027 в РФ      |
| `observance` | по неделе | праздник без выходного: памятная дата или праздник при военном положении            | 24 августа 2026 в UA |

Дополнительные поля:

- `holiday` — id из `countries/<id>.json → holidays`
- `transfer.from` / `transfer.to` — откуда пришёл или куда ушёл выходной (нужно, чтобы рисовать стрелку переноса)
- `basis` — `decree` (постановление) | `weekend-holiday-rule` (автоматический перенос по закону)
- `shortBy` — на сколько часов короче день
- `tentative` — дата может сдвинуться (лунные праздники, прогноз)
- `regime` — день изменён особым режимом (военное положение)

## Как вычислить день

```
entry = year.days[date]
off   = entry.type in (holiday, dayoff) ? true
      : entry.type == workday           ? false
      : weekday(date) in country.week.weekend
hours = off ? 0 : hoursPerDay[weekHours] - (entry.shortBy ?? 0)
```

Отпуск:

```
unit == "calendar": списываем все дни периода, кроме тех, чей type входит в leave.notCounted
unit == "working":  списываем только рабочие дни (off == false)
```

Режим (`regimes`) может переопределить `leave.notCounted`. Например, при военном положении в Украине
праздники списываются из отпуска.

## Как добавится США

```jsonc
"week": { "start": 7, "weekend": [6, 7] },          // неделя с воскресенья
"rules": { "weekendHoliday": "nearest-weekday" },     // сб → пт, вс → пн (observed)
"leave": { "unit": "working", "minDays": null },      // PTO задаёт компания
"holidays": { "thanksgiving": { "rule": { "nthWeekday": { "month": 11, "weekday": 4, "n": 4 } } } },
"pages": { "en": "United States", "ru": "США" }      // свои страницы: /en/us/2027/, /ru/us/2027/
```

Перенос назад (с субботы на пятницу) записывается тем же `dayoff` с `transfer.from`.
Штаты и регионы РФ (Татарстан, Башкортостан) можно хранить отдельными файлами
`years/us-ca/2027.json` с полем `extends: "us"`.

## Сверка

Итоги года (рабочие дни, нормы часов) в файлах не хранятся: их считает код
(`src/domain/calendar.ts → yearTotals`). Если у года есть `officialNorms` из постановления,
тест `src/data/data.test.ts` сверяет с ними расчёт. Сейчас сходятся до часа:
RU 2026 и 2027, BY 2026 и 2027, KZ 2026.

## Как добавить год

1. Создайте `years/<страна>/<год>.json`: `status`, `sources` и в `days` только отличия от обычной недели.
2. Если опубликованы официальные нормы, добавьте `officialNorms`.
3. Запустите `npm test`: тест проверит ссылки на праздники, парность переносов и нормы.

## Оплачиваемые дни отпуска (`leave.pay`)

Какие дни оплачиваются отпускными. Если оплачиваются рабочие дни внутри отпуска,
а сам отпуск считается в календарных днях, итог отпуска дополнительно показывает число рабочих дней.
Новой стране с такими правилами достаточно указать `"days": "workdays"`, код менять не нужно.

```jsonc
"pay": {
	"days": "charged",   // списанные дни (charged) или рабочие дни внутри отпуска (workdays)
	"source": "https://…" // откуда правило
}
```

| Страна    | days     |
| --------- | -------- |
| Россия    | charged  |
| Беларусь  | charged  |
| Украина   | charged  |
| Казахстан | workdays |
| Армения   | workdays |

## Страницы страны (`pages`)

У каждой страны есть свои страницы вида `/ru/kz/2026/` под поисковые запросы
вроде «производственный календарь казахстан 2026». Поле `pages` задаёт белый список языков
для них и форму названия, которая встаёт в заголовок:

```jsonc
"pages": {
	"ru": "Казахстана",    // «Производственный календарь Казахстана на 2026 год»
	"kk": "Қазақстанның",  // «Қазақстанның 2026 жылғы өндірістік күнтізбесі»
	"en": "Kazakhstan"     // «Kazakhstan working calendar 2026»
}
```

Берите язык страны, русский (тест требует его у всех) и английский. Не добавляйте языки, на которых
страну никто не ищет: каждая пара «страна + язык» — это отдельная страница на каждый год,
а пустые страницы поисковики не любят. Новая страна добавляет страницы только на своих языках,
поэтому их число растёт линейно.

## Переводы

Названия стран и праздников лежат в `name` на шести языках: ru, en, kk, hy, be, uk,
формы названий для заголовков страниц — в `pages`.
Переводы на kk, hy, be и uk сделаны без носителя языка. Если видите ошибку, поправьте её в JSON.

## Что ещё проверить

- **AM, 8 марта**: в доступной редакции закона статья 3 обрезана. Нерабочий статус взят из справочников.
- **KZ 2027, AM 2027, UA 2027**: это прогноз. Ждём постановлений о переносах и продления военного положения.
- **BY, № 499**: номер постановления на 2027 год взят из пересказа. Сверить на pravo.by.
- **Пасха в BY** (католическая и православная, всегда в воскресенье): пока не внесена. Если это праздничный нерабочий день, то при календарном отпуске она его продлевает.
