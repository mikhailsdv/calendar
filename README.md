# Производственный календарь

Праздники, переносы и выходные России, Казахстана, Беларуси, Армении и Украины на одном календаре.
Нормы дней и часов по месяцам и кварталам, шестидневка, отпуск по правилам каждой страны
и сравнение до пяти стран на одном календаре.

**Сайт:** https://calendar.mishasaidov.com

> **English.** A working-days calendar for Russia, Kazakhstan, Belarus, Armenia and Ukraine. Monthly and quarterly
> norms of days and hours, six-day week, transferred days off, leave counted under each country's rules,
> and up to five countries compared on one calendar.
> Static site built with Preact and Vite, prerendered in six languages.

![Обложка](public/og/ru.png)

## Возможности

- **Два вида:** год по кварталам (итоги дней и часов у квартала и каждого месяца) и месяц.
- **Одна страна по умолчанию, сравнение по кнопке.** «Сравнить» накладывает до 5 стран: нерабочие дни основной страны красные, нерабочие будни других стран отмечены точками их цвета. Выбранные страны помнятся в `localStorage`.
- **Своя страна сразу.** При первом входе страна определяется по часовому поясу браузера, если он из одной из пяти стран, иначе по языку страницы или региону в языке браузера. Без запросов к сервисам геолокации.
- **Переносы.** Нажмите на перенесённый выходной — календарь нарисует дугу к дню-источнику.
- **Отпуск на календаре.** Нажмите на первый и последний день. На компьютере до наведённой даты рисуется тусклое превью. По каждой стране видно, сколько дней спишется, сколько праздников внутри и сколько всего дней отдыха. Если отпускные платят за рабочие дни (`leave.pay.days`), видно и их число.
- **Шестидневка** в настройках: выходной только воскресенье, переносы по постановлению не действуют, норма часов как при пятидневке.
- **Ближайшие праздники** выбранных стран с обратным отсчётом и длиной отдыха. Нажатие прокручивает календарь к дате.
- **Печать:** год помещается на один лист A4, красные дни и цвета стран сохраняются, списки праздников печатаются раскрытыми.
- **Номера недель** (включаются в настройках), свайп между месяцами на телефоне.
- **Итоги года:** рабочие и выходные дни, праздники, норма часов, минимальный отпуск, нормы по месяцам; при сравнении — по каждой стране.
- **6 языков:** русский, английский, казахский, армянский, белорусский, украинский. Язык определяется автоматически, запасной — русский.
- Светлая и тёмная тема, настройки в `localStorage`, работа без наведения на тач-устройствах.

## Данные

Календари лежат в [`data/`](data/) в формате JSON: профиль страны и файл на каждый год. В файле года хранятся
только отличия от обычной недели. Формат, правила расчёта и способ добавить год описаны в [`data/README.md`](data/README.md).

Каждый год сверяется с официальными нормами в тестах. Если нашли ошибку в данных, откройте issue со ссылкой на источник.

## Стек

- [Preact](https://preactjs.com) и [@preact/signals](https://preactjs.com/guide/v10/signals), [Vite](https://vite.dev)
- Пререндер страниц через `@preact/preset-vite`: каждая страница отдаётся готовым HTML, SSR не нужен
- TypeScript, CSS Modules, без UI-китов и библиотек дат
- Vitest и Testing Library, ESLint и Prettier, size-limit

## Разработка

Нужен Node.js 22.

```bash
npm install
npm run dev          # http://localhost:5173
npm test             # юнит-тесты, тесты компонентов и данных
npm run lint         # ESLint и Prettier
npm run typecheck
npm run build        # сборка с пререндером в dist/
npm run test:dist    # проверка собранных страниц: мета-теги, hreflang, sitemap
npm run size-limit   # бюджет размера JS и CSS
npm run preview      # собранный сайт на http://localhost:4173
npm run og           # перегенерировать OG-обложки и иконки в public/
npm run goals        # пересобрать список целей Метрики в docs/
```

## Страницы и SEO

- `/` — выбор языка. Скрипт в `index.html` сразу перенаправляет на сохранённый или определённый язык.
- `/{язык}/` — календарь на текущий год, `/{язык}/{год}/` — страница года.
- `/{язык}/{страна}/` и `/{язык}/{страна}/{год}/` — страницы страны: «Производственный календарь Казахстана
  на 2026 год». Они есть только на языках из поля `pages` профиля страны (обычно язык страны,
  русский и английский), поэтому число страниц растёт линейно, а не перемножается.
- У каждой страницы свои title, description, canonical, hreflang, Open Graph и JSON-LD.
- `sitemap.xml` собирается при сборке из тех же групп страниц, что и hreflang. `robots.txt` и `.htaccess` лежат в `public/`.

## Деплой

Сайт статический, его можно положить на любой хостинг. В проекте настроен деплой по FTP на PHP-хостинг без SSH:
GitHub Actions собирает сайт, заливает один zip-архив и распаковщик `ci/deploy.php` под случайным именем,
а затем вызывает распаковщик по HTTP, пока тот не ответит `DEPLOY_OK`.

> ⚠️ Распаковщик удаляет из целевой папки всё, чего нет в сборке. Папка на хостинге должна принадлежать только этому сайту.

Workflow `.github/workflows/deploy.yml` запускается вручную из `main` и сам пересобирает сайт 1 января,
чтобы корневые страницы открывались на новом году. Для него в настройках репозитория нужны:

| Где     | Имя              | Пример                                     |
| ------- | ---------------- | ------------------------------------------ |
| Secrets | `FTP_HOST`       | `ftp.example.com`                          |
| Secrets | `FTP_USER`       |                                            |
| Secrets | `FTP_PASSWORD`   |                                            |
| Secrets | `FTP_TARGET_DIR` | `httpdocs/` (со слешем на конце)           |
| Secrets | `DEPLOY_URL`     | `https://calendar.mishasaidov.com`         |
| Secrets | `YM_ID`          | ID счётчика Яндекс Метрики (необязательно) |

Все значения — секреты: в публичном репозитории логи Actions видны всем, а обычные переменные в них
печатаются открытым текстом. Если сайт лежит прямо в корне FTP, секрет `FTP_TARGET_DIR` не создавайте:
пустое значение GitHub не сохранит, а отсутствующий секрет и так подставится пустой строкой.

## Аналитика

Счётчик Яндекс Метрики подключается, только если при сборке задан `VITE_YM_ID`. В форках без этой переменной
аналитика выключена. Настройки те же, что в коде счётчика из интерфейса Метрики: Вебвизор, карта кликов,
внешние ссылки, точный показатель отказов. Отличие одно: скрипт счётчика грузится после загрузки страницы
и не влияет на её скорость, а визит и цели до этого копятся в очереди. Для посетителей без JavaScript
в каждую страницу добавляется пиксель `<noscript>`.

Проверить локально: `VITE_YM_ID=<ID счётчика> npm run build && npm run preview`.
Все цели с описанием параметров перечислены в [`src/analytics/events.json`](src/analytics/events.json).
Готовый список для настройки целей в Метрике — [`docs/metrika-goals.md`](docs/metrika-goals.md), он собирается командой `npm run goals`.
